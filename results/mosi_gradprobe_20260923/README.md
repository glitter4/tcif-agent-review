# MOSI：固定训练batch的配对梯度诊断

2026-09-23。使用既有checkpoint进行12个只读探针，全部完成；**没有训练、优化器step、新checkpoint或新test指标**。固定训练集前8个microbatch16，按原accum2组成4个有效batch32，共128条唯一训练样本。D1使用epoch59，R1使用同一次训练的epoch58与149。D1原best-Acc7和best-MAE同epoch，不重复跑同一权重。

| checkpoint与条件 | 每条件样本 | 模式 |
|---|---:|---|
| D1 epoch59，邻居完整/临时detach | 128 | eval、训练模式dropout种子123和124；三组严格配对 |
| R1 epoch58、149 | 各128 | eval、训练模式dropout种子123和124 |

D1三组完整/detach配对的sample ID、原标签和回归/7维logits前向**逐值一致**；所有12组的权重及buffer前后均逐值不变。所有条件使用相同128条训练样本，标签7条精确零、64条正非零、57条负非零；其中53条有至少一个非零异极性有效邻居，102条有至少一个同极性有效邻居，两类可重叠。有效邻居槽位247个，异极性64，同极性157；没有无邻居样本。

## 观察到的方向与波动

表内余弦为**加权softCE相对L1回归在router-phi组**的4个有效batch中位数；括号表示负值batch数。均为同一checkpoint内部计算，并非新训练收益。

| 条件 | 完整邻居路径 | 邻居detach |
|---|---:|---:|
| D1 eval | −.794（3/4） | −.783（3/4） |
| D1 训练模式，dropout种子123 | −.612（3/4） | −.578（3/4） |
| D1 训练模式，dropout种子124 | −.452（3/4） | −.449（3/4） |

邻居detach改变部分梯度范数与方向，但未将router-phi的负夹角一致消除；与既有DETACH完整训练未产生联合指标突破相符，仍不能由这些batch证明邻居路径是性能瓶颈。

| R1 checkpoint | eval | 训练种子123 | 训练种子124 |
|---|---:|---:|---:|
| epoch58 | −.272（2/4） | −.232（3/4） | −.037（3/4） |
| epoch149 | −.246（3/4） | +.184（2/4） | −.294（4/4） |

R1的同一阶段在不同dropout种子下也会变号；现有4个batch不能支持“后期持续冲突”或“升高全局clip会改善性能”。D1 eval的共享专家组余弦中位数约−.084，四个batch都为负但幅度小；D1同条件的文本最后一层约+.298、四个batch均非负。不同参数组不能用一个router值概括。

TCIF回归与分类模块部分参数只连接各自loss，其余弦**记N/A并注明无路径**。`batches[].groups`包含router phi/scale、共享/专属专家、RoBERTa逐层、TCIF回归/分类/gate、task pooling与输出头的逐batch范数、内积、余弦及连接信息。没有把None当成零夹角。门控监督的加权梯度单列，所有组互不重叠；每条件完整参数组的裁剪前全局范数与`clip=1`缩放系数均在逐batch原始记录中。

这些是固定训练样本上的局部梯度，不是训练期间多个真实时间点的连续历史。R1 epoch58/149两个checkpoint的比较不能补出缺失的早期优化器状态。正比例裁剪本身不改变两分项梯度的夹角；也不能从裁剪系数直接推断AdamW真实更新比例。
